# AssetFactory MCP Generator Exposure Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `StateTree`, `BehaviorTree`, and `BlackboardData` first-class MCP generator types with schema docs and schema-level regression tests.

**Architecture:** Keep this as a TypeScript/docs-only MCP contract change. Centralize the MCP generator asset type list in `MCP/src/index.ts`, add missing schema markdown files for existing BT/BB generators, keep StateTree docs readable in Chinese, and lock the whole surface with Node tests that do not need Unreal Editor.

**Tech Stack:** TypeScript MCP server, Node `node:test`, Markdown schema docs, existing AssetFactory JSON fixtures.

Create `MCP/src/broker/generatorSchemas.test.ts` with this content:

```ts
import test from "node:test";
import assert from "node:assert/strict";
import { dirname, join } from "path";
import { fileURLToPath } from "url";

import { Client } from "@modelcontextprotocol/sdk/client/index.js";
import { StdioClientTransport } from "@modelcontextprotocol/sdk/client/stdio.js";

const DIST_DIR = dirname(dirname(fileURLToPath(import.meta.url)));
const PROJECT_DIR = dirname(DIST_DIR);
const SERVER_ENTRY = join(DIST_DIR, "index.js");
const CHILD_ENV = Object.fromEntries(
	Object.entries(process.env).filter((entry): entry is [string, string] => typeof entry[1] === "string"),
);

async function withClient(run: (client: Client) => Promise<void>): Promise<void> {
	const transport = new StdioClientTransport({
		command: process.execPath,
		args: [SERVER_ENTRY],
		cwd: PROJECT_DIR,
		env: CHILD_ENV,
		stderr: "pipe",
	});
	const client = new Client({ name: "Codex", version: "desktop" }, { capabilities: {} });

	try {
		await client.connect(transport);
		await run(client);
	} finally {
		await client.close().catch(() => undefined);
		await transport.close().catch(() => undefined);
	}
}

function textContent(result: { content?: unknown }): string {
	assert.ok(Array.isArray(result.content));
	return result.content
		.filter(
			(entry): entry is { type: "text"; text: string } =>
				typeof entry === "object" && entry !== null && "type" in entry && entry.type === "text" && "text" in entry,
		)
		.map((entry) => entry.text)
		.join("\n");
}

test("generator schemas are readable for StateTree, BehaviorTree, and BlackboardData", async () => {
	await withClient(async (client) => {
		const expected = [
			{
				assetType: "StateTree",
				patterns: [/StateTree/, /RootParameters/, /bindings/, /round-trip/i],
			},
			{
				assetType: "BehaviorTree",
				patterns: [/BehaviorTree/, /BlackboardInline/, /Root/, /BTTask_RunBehavior/],
			},
			{
				assetType: "BlackboardData",
				patterns: [/BlackboardData/, /Keys/, /BaseClass/, /bInstanceSynced/],
			},
		] as const;

		for (const entry of expected) {
			const result = await client.callTool({
				name: "get_generator_schema",
				arguments: { asset_type: entry.assetType },
			});

			assert.notEqual(result.isError, true, `${entry.assetType} schema call should succeed`);
			const text = textContent(result);
			for (const pattern of entry.patterns) {
				assert.match(text, pattern, `${entry.assetType} schema should include ${pattern}`);
			}
		}
	});
});

test("generate_assets and get_generator_schema advertise StateTree, BehaviorTree, and BlackboardData", async () => {
	await withClient(async (client) => {
		const listed = await client.listTools();
		const generateAssets = listed.tools.find((tool) => tool.name === "generate_assets");
		const getSchema = listed.tools.find((tool) => tool.name === "get_generator_schema");

		assert.ok(generateAssets, "generate_assets should be visible");
		assert.ok(getSchema, "get_generator_schema should be visible");

		const generateSchema = JSON.stringify(generateAssets.inputSchema);
		const getSchemaInput = JSON.stringify(getSchema.inputSchema);
		for (const assetType of ["StateTree", "BehaviorTree", "BlackboardData"]) {
			assert.match(generateSchema, new RegExp(assetType), `generate_assets should mention ${assetType}`);
			assert.match(getSchemaInput, new RegExp(assetType), `get_generator_schema should mention ${assetType}`);
		}
	});
});

test("missing schema fallback lists StateTree, BehaviorTree, and BlackboardData", async () => {
	await withClient(async (client) => {
		const result = await client.callTool({
			name: "get_generator_schema",
			arguments: { asset_type: "DefinitelyMissingGenerator" },
		});

		assert.notEqual(result.isError, true);
		const text = textContent(result);
		for (const assetType of ["StateTree", "BehaviorTree", "BlackboardData"]) {
			assert.match(text, new RegExp(assetType), `fallback should mention ${assetType}`);
		}
	});
});
```

- [ ] **Step 1: Add BehaviorTree schema doc**

Create `MCP/schemas/BehaviorTree.md` with this content:

````markdown
# BehaviorTree 生成器 Schema

通过已有 `BehaviorTree` generator 创建或更新 UE 行为树资产。本文只描述当前 generator 已支持的 JSON 契约，不新增行为树语义。

## 顶层字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `AssetType` | string | 是 | 必须是 `"BehaviorTree"` |
| `Name` | string | 是 | 行为树资产名 |
| `Path` | string | 是 | 内容目录，例如 `"/Game/AI"` |
| `Action` | string | 否 | `"Create"`、`"Update"` 或 `"CreateOrUpdate"` |
| `Blackboard` | string | 否 | 已存在 `UBlackboardData` 资产路径 |
| `BlackboardInline` | object | 否 | 内联创建 blackboard，形状同 `BlackboardData` schema |
| `Root` | object | 是 | 根行为树节点，必须解析为 `UBTCompositeNode` 子类 |

`Blackboard` 和 `BlackboardInline` 互斥。引用已有 blackboard 时，路径可以是 `/Game/AI/BB_Enemy` 或完整 object path。使用 `BlackboardInline` 时，generator 会先创建或更新对应 `BlackboardData`，再把它挂到行为树。

## 基础示例

```json
{
	"AssetType": "BehaviorTree",
	"Name": "BT_Enemy",
	"Path": "/Game/AI",
	"Blackboard": "/Game/AI/BB_Enemy",
	"Root": {
		"Node": "BTComposite_Selector",
		"InstanceName": "RootSelector",
		"Children": [
			{
				"Node": "BTTask_Wait",
				"Properties": {
					"WaitTime": { "DefaultValue": 1.0 }
				}
			}
		]
	}
}
```

## 内联 Blackboard 示例

```json
{
	"AssetType": "BehaviorTree",
	"Name": "BT_EnemyInline",
	"Path": "/Game/AI",
	"BlackboardInline": {
		"Name": "BB_EnemyInline",
		"Path": "/Game/AI",
		"Keys": [
			{ "Name": "HasTarget", "Type": "Bool" },
			{ "Name": "MoveLocation", "Type": "Vector" }
		]
	},
	"Root": {
		"Node": "BTComposite_Sequence",
		"Children": [
			{ "Node": "BTTask_Wait" }
		]
	}
}
```

## 节点形状

行为树节点使用同一个 JSON 形状：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `Node` | string | composite/task 是 | `UBTCompositeNode` 或 `UBTTaskNode` 类名、完整类名或路径 |
| `Type` | string | decorator/service 是 | `UBTDecorator` 或 `UBTService` 类名、完整类名或路径 |
| `InstanceName` | string | 否 | 写入节点的 `NodeName`，便于编辑器识别 |
| `Properties` | object | 否 | 通过反射写入节点 UObject 属性 |
| `Children` | array | composite 是 | 子节点数组；只有 composite 可以拥有 children |
| `Decorators` | array | 否 | 挂在当前 child link 上的 decorators |
| `Services` | array | 否 | 挂在 composite 节点上的 services |

根节点必须是 composite。Composite 节点必须提供非空 `Children`。Task 节点不能提供 `Children`。当前 generator 只支持 composite-level `Services`；task-level services 不属于本契约。

## Decorator 示例

```json
{
	"Node": "BTComposite_Sequence",
	"Children": [
		{
			"Node": "BTTask_Wait",
			"Decorators": [
				{
					"Type": "BTDecorator_Blackboard",
					"Properties": {
						"BlackboardKey": {
							"SelectedKeyName": "HasTarget"
						}
					}
				}
			]
		}
	]
}
```

Generator 会反射检查 `FBlackboardKeySelector` 属性，并验证引用的 key 存在于当前 blackboard 或其 parent chain 中。

## Subtree 示例

```json
{
	"AssetType": "BehaviorTree",
	"Name": "BT_EnemyMain",
	"Path": "/Game/AI",
	"Blackboard": "/Game/AI/BB_Enemy",
	"Root": {
		"Node": "BTComposite_Sequence",
		"Children": [
			{
				"Node": "BTTask_RunBehavior",
				"Properties": {
					"BehaviorAsset": "/Game/AI/BT_EnemyShared"
				}
			}
		]
	}
}
```

引用 subtree 时，generator 会检查 `BehaviorAsset` 是否能加载，并验证子行为树 blackboard 与父行为树兼容。

## 常见失败

- `Blackboard and BlackboardInline are mutually exclusive`：同时提供了 `Blackboard` 和 `BlackboardInline`。
- `Root node '<name>' must be a UBTCompositeNode subclass`：根节点不是 composite。
- `Composite node '<name>' must have at least one child`：composite 的 `Children` 为空。
- `Non-composite node '<name>' cannot have 'Children'`：task 节点声明了 children。
- `Resolved class '<name>' is not a UBTDecorator subclass`：decorator 类型不合法。
- `Only composite nodes can define Services`：非 composite 节点声明了 services。
- `Blackboard key '<name>' is not present in the behavior tree blackboard`：节点、decorator 或 service 引用了不存在的 blackboard key。
````

- [ ] **Step 1: Add BlackboardData schema doc**

Create `MCP/schemas/BlackboardData.md` with this content:

````markdown
# BlackboardData 生成器 Schema

通过已有 `BlackboardData` generator 创建或更新 UE blackboard 资产。该 generator 的优先级高于 `BehaviorTree`，所以同一个 `generate_assets` 请求中可以先写 blackboard，再写引用它的 behavior tree。

## 顶层字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `AssetType` | string | 是 | 必须是 `"BlackboardData"` |
| `Name` | string | 是 | blackboard 资产名 |
| `Path` | string | 是 | 内容目录，例如 `"/Game/AI"` |
| `Action` | string | 否 | `"Create"`、`"Update"` 或 `"CreateOrUpdate"` |
| `Parent` | string | 否 | parent blackboard 资产路径 |
| `Keys` | array | 是 | 非空 key 定义数组 |

## 示例

```json
{
	"AssetType": "BlackboardData",
	"Name": "BB_Enemy",
	"Path": "/Game/AI",
	"Keys": [
		{ "Name": "TargetActor", "Type": "Object", "BaseClass": "/Script/Engine.Actor" },
		{ "Name": "HasTarget", "Type": "Bool", "bInstanceSynced": true },
		{ "Name": "MoveLocation", "Type": "Vector" },
		{ "Name": "TargetTag", "Type": "Name" },
		{ "Name": "Score", "Type": "Int" },
		{ "Name": "Speed", "Type": "Float" }
	]
}
```

## Key 形状

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `Name` | string | 是 | blackboard key 名称，同一资产内必须唯一 |
| `Type` | string | 是 | key 类型 |
| `BaseClass` | string | Object/Class 必填 | `Object` 或 `Class` key 的 base class |
| `EnumName` | string | Enum 必填 | `Enum` key 的枚举路径、名称或 object path |
| `bInstanceSynced` | bool | 否 | 是否启用 instance synced |
| `Description` | string | 否 | key 描述 |

支持的简写类型包括：

- `Bool`
- `Int`
- `Float`
- `String`
- `Name`
- `Vector`
- `Rotator`
- `Object`
- `Class`
- `Enum`

也可以使用完整 `UBlackboardKeyType` class 路径，但推荐使用上面的简写。

## Parent 示例

```json
{
	"AssetType": "BlackboardData",
	"Name": "BB_EnemyBoss",
	"Path": "/Game/AI",
	"Parent": "/Game/AI/BB_Enemy",
	"Keys": [
		{ "Name": "Phase", "Type": "Int" }
	]
}
```

## Object / Class / Enum 示例

```json
{
	"Keys": [
		{ "Name": "TargetActor", "Type": "Object", "BaseClass": "/Script/Engine.Actor" },
		{ "Name": "TargetClass", "Type": "Class", "BaseClass": "/Script/Engine.Pawn" },
		{ "Name": "CombatState", "Type": "Enum", "EnumName": "/Script/ProjectRPG.ERPGCombatState" }
	]
}
```

## 常见失败

- `'Keys' must be a non-empty array`：`Keys` 缺失或为空。
- `Keys[n].Name must be a non-empty string`：key name 缺失。
- `Duplicate blackboard key name '<name>'`：同一 blackboard 内 key 重名。
- `Keys[n] ('<name>') has unsupported Type '<type>'`：无法解析 key type。
- `Keys[n] ('<name>') requires a non-empty BaseClass`：`Object` 或 `Class` key 缺少 `BaseClass`。
- `Keys[n] ('<name>') requires a non-empty EnumName`：`Enum` key 缺少 `EnumName`。
````
